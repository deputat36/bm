# City catalog coverage map

Дата фиксации: 2026-08-09

## Назначение

`data/research/city-catalog-coverage.json` отвечает на один вопрос: все ли уже обнаруженные в текущих публичных источниках объекты сопоставлены с каноническими реестрами портала.

Это не реестр для frontend и не доказательство абсолютной полноты новостроек Борисоглебска.

## Три допустимых назначения наблюдения

Каждый обнаруженный объект должен вести ровно в один из слоёв:

- `priority` — один из трёх приоритетных объектов, для которых действует отдельная verification/source очередь;
- `reference` — уже подтверждённая справочная карточка городского каталога;
- `candidate` — исследовательский адрес, который пока не прошёл publication threshold.

Если точной связи нет, объект не должен оставаться без статуса: для него создаётся candidate с acceptance gaps. Но candidate не рендерится публично.

## Текущий snapshot

На 9 августа 2026 года карта учитывает:

- 3/3 priority projects;
- 4/4 public reference projects;
- 2/2 unresolved reference candidates;
- 11 наблюдений в шести source-группах;
- 0 наблюдений без registry mapping.

Одно наблюдение может быть частью уже объединённого объекта. Например, Уютная 5А и Дорожная 50А представлены в portal registry одной справочной карточкой ЖК «Уютный», поскольку такое объединение подтверждается официальным источником застройщика.

Аналогично вторичный жилищный реестр обнаруживает дом `мкр. Восточный, 1` как дом 2020 года. Это не создаёт новую reference-карточку: marketplace discovery связывает `мкр. Восточный, 1` и `мкр. Восточный, 3` с уже зарегистрированным ЖК «Европейский», а официальный сайт ГК «Проект Инвест» подтверждает сам комплекс и застройщика. Точные адреса отдельных очередей по-прежнему не повышаются до buyer-facing факта без первичного address-level evidence.

Evidence этого прохода: `docs/portal/research/CITY_CATALOG_STOCK_SCAN_2026-08-09.md`.

## Почему snapshot не равен полной инвентаризации города

Публичные агрегаторы могут не содержать исторические дома, малые проекты, отдельные очереди или ещё не опубликованные планы. Наличие объекта в агрегаторе не делает его первичным источником, а отсутствие — не доказывает отсутствие самого объекта.

Жилищные реестры вторичного уровня полезны для поиска адресов и проверки дублей, но не считаются исчерпывающим перечнем домов по годам. Проверенный 9 августа secondary housing-stock index заканчивает перечень годов Борисоглебска 2020 годом, хотя в других источниках уже видны более новые объекты. Поэтому такой источник особенно полезен как discovery clue и отрицательный тест полноты, но не как completeness authority.

Отдельная воспроизводимая методика теперь формализована в `data/research/city-inventory-method.json` и описана в `docs/portal/CITY_INVENTORY_METHOD.md`. Она требует системно пройти разрешительные/вводные реестры, ЕИСЖС или эквивалентный primary project source, официальные developer-портфели, муниципальные планировочные/адресные публикации и финальное entity reconciliation.

Пока эти обязательные scans не пройдены, `research_queue_complete=false` и `inventory_complete=false` сохраняются независимо от того, сколько агрегаторов перестали показывать новые результаты.

## Использование вторичных источников

Яндекс Недвижимость, ЦИАН и жилищные агрегаторы используются только для discovery, entity resolution и cross-check. Они не повышают critical claims priority-object до confirmed и не могут сами по себе создать public-ready reference-card, если нет достаточного evidence по адресу, статусу и объектной идентичности.

Для каждого `source_class`, начинающегося с `secondary_`, coverage map обязана явно хранить:

```text
completeness_use_allowed=false
limitations=[...]
```

Это делает ограничение машиночитаемым: secondary source не может быть случайно переиспользован как доказательство завершённой инвентаризации города.

Официальные страницы застройщиков, регуляторов и иные первичные/официальные публикации используются в пределах конкретно поддерживаемых ими утверждений.

## Автоматическая защита

`tools/validate-city-catalog-coverage.mjs` сравнивает snapshot с актуальными реестрами и падает, если:

- изменился состав priority/reference/unresolved candidates, но coverage map не обновлена;
- наблюдение ссылается на неизвестный project ID;
- unresolved candidate ошибочно сопоставлен как reference;
- promoted candidate продолжает использоваться как candidate;
- есть observation без mapping;
- secondary source не имеет `completeness_use_allowed=false` и документированных limitations;
- snapshot пытается объявить research queue завершённой;
- public catalog/runtime начинает загружать research-only coverage JSON.

`tools/validate-city-inventory-method.mjs` отдельно проверяет, что завершение Phase C возможно только по формализованной методике и не смешивается с legal/media/publication readiness конкретных карточек.

GitHub Actions guards содержат отрицательные тесты ложной полноты, secondary completeness authority и преждевременного inventory completion.
