# Buyer-content standard — Аэродромная 18Г и Сенная 76

Дата: 2026-08-09

## Зачем нужен guard

Карточки Аэродромной 18Г и Сенной 76 уже содержат полезный покупательский контент, хотя их primary-source verification ещё не завершена.

Риск следующего этапа — либо случайно удалить buyer-facing блоки при обновлении источников, либо наоборот превратить неподтверждённые юридические/коммерческие сведения в безусловные факты.

`tools/validate-priority-buyer-content.mjs` защищает существующее безопасное равновесие.

## Общий стандарт

Для каждой из двух карточек обязательны одновременно:

- понятное описание объекта;
- блок известных/атрибутированных характеристик;
- явный источник информации;
- явная граница достоверности;
- отдельный pending-блок первичных документов/сделки;
- FAQ;
- короткая форма `quick-lead`;
- подробная форма `lead`;
- обе формы входят в канонический `form-scenarios.json` как `primary` + `detailed`;
- обе формы остаются fail-closed;
- страница остаётся `noindex,follow`, пока verification profile не confirmed;
- цены и наличие не считаются покрытыми текущим verification profile.

## Аэродромная 18Г

Buyer-content может использовать только claims, которые verification profile разрешает публиковать.

Сейчас это:

- адрес и название ЖК «Патриот»;
- атрибутированное исправление ошибочного названия ЦИАН;
- атрибутированное указание ЦИАН на предполагаемого застройщика;
- общие marketplace-характеристики: тип дома, диапазон этажности, потолки, черновая отделка, парковка и элементы территории.

Страница обязана одновременно объяснять, что первично не подтверждены:

- статус ввода нужной секции;
- разрешения;
- продавец;
- договор;
- цена/наличие;
- ипотека по конкретной квартире.

Marketplace/owner claims не заменяют primary object evidence.

## Сенная 76

Buyer-content основан на проверенном публичном интервью представителя компании-застройщика.

Разрешено атрибутированно рассказывать о заявленных:

- фасаде и кровле;
- утеплении;
- индивидуальном отоплении;
- системе «умный дом»;
- благоустройстве;
- освещении/датчиках;
- отделке общих зон;
- видеонаблюдении.

Страница обязана объяснять, что интервью не подтверждает:

- разрешение на ввод;
- юридическое лицо застройщика/продавца;
- ЕГРН конкретной квартиры;
- квартирографию и площади;
- актуальную цену/наличие;
- договорную схему.

## Связь с verification profile

Guard не хранит вторую копию характеристик.

Для каждого `publication_allowed=true` claim он проверяет:

1. `verification_status=confirmed`;
2. наличие `source_ids`;
3. существование каждого source;
4. `source.status=verified`;
5. HTTPS reference для каждого verified source.

Таким образом buyer-page не может опираться на claim, который verification profile перестал разрешать.

## Формы

Источник истины по form IDs и ролям — `data/qa/form-scenarios.json`.

Для каждой страницы требуется ровно два сценария:

```text
primary  -> #quick-lead
detailed -> #lead
```

Оба имеют `lead_type=project_consultation`, а corresponding `data-form-id` должен встречаться на странице ровно один раз.

## Что этот guard не утверждает

Успешный buyer-content guard не означает:

- `is_public_ready=true`;
- source completion;
- legal approval;
- media rights;
- разрешение индексации;
- разрешение рекламы;
- актуальность цены или наличия.

Он означает только, что текущая source-gated noindex-карточка остаётся полезной покупателю и не потеряла явные ограничения достоверности.
