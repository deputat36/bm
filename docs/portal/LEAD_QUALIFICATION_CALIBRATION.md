# Калибровка оценки намерения покупателя

Дата: 2026-10-14

## Почему понадобилась корректировка

`qualifyLead` в `assets/js/main.js` ранее вычислял бюджет через `data.budget || data.comment`. Любой непустой комментарий, даже «Расскажите о документах», приносил **+15 за бюджет**, которого покупатель не указывал. Также неопределённые ответы («Пока не определился», «Пока изучаю варианты», «Нужна консультация по вариантам») могли ошибочно добавлять баллы за конкретный выбор.

Это ухудшало приоритеты обработки: заявка с произвольным текстом могла перейти в `warm`/`hot` без реального финансового ориентира или готовности к покупке.

## Правила после исправления

- `budget` оценивается **только из одноимённого поля**; `comment` сохраняется для специалиста, но не заменяет бюджет.
- Комнатность/вопрос дают +10 только при конкретном выборе.
- Способ покупки даёт +15, только если пользователь указал сам способ; «Нужна консультация по вариантам» не является известным способом.
- Срок покупки даёт +20 при явной краткосрочной формулировке и +8 за другой **конкретно указанный** срок; «Пока изучаю варианты» не считается сроком.
- Поле `lead_type=mortgage` продолжает давать сигнал необходимости ипотечной консультации: покупатель явно находится в ипотечном сценарии, даже если программу ещё не выбрал.
- Баллы за телефон (+15), обратный звонок (+15), ипотечный интерес (+10), встречную продажу (+8) и границы `cold < 40`, `warm 40–64`, `hot >= 65` не изменены.

Это эвристика маршрутизации, **не** скоринг кредитоспособности и не гарантия заключения сделки. `priority` — внутренняя рекомендация, а не согласованный SLA.

## Регрессия

`node tools/test-lead-qualification.mjs` запускает актуальную функцию `qualifyLead` из production JavaScript в изолированной среде. 12 сценариев покрывают комментарий без бюджета, неопределённые значения, реальный финансовый ориентир, ипотеку, запрос звонка, долгий срок и границы `cold/warm/hot`.

Тест не запускает форму, не отправляет HTTP-запросы, не записывает контакты и не повышает ни один release gate.

## Что не изменилось

Схема заявки, `FormData`, источник/UTM, согласие, payload, endpoint Supabase, расчёт валидности телефона, события аналитики, объектные идентификаторы и тексты юридических ограничений. Исторические заявки автоматически не пересчитываются.

Применение приоритета в реальной операционной обработке требует соответствующих owner/operations approvals; эта корректировка сама по себе не разрешает коммерческий запуск.
