# ЕИСЖС / наш.дом.рф — primary project scan Борисоглебска

Дата: 2026-08-09

## Цель

`data/research/eiszh-primary-scan.json` отделяет четыре разных уровня evidence, которые раньше легко было смешать:

1. публичный маршрут карточек ЕИСЖС существует;
2. известен candidate object ID;
3. сторонняя площадка маркирует ЖК как проверенный наш.дом.рф;
4. прочитана именно целевая первичная карточка и её идентичность совпала.

Только четвёртый уровень позволяет принять карточку ЕИСЖС как primary object evidence.

## Публичный route pattern

Поисковая индексация показывает официальные страницы ЕИСЖС вида:

```text
https://наш.дом.рф/сервисы/проверка_новостроек/{numeric_object_id}
```

Например, публично индексируется объект ID `65533`.

Это подтверждает существование numeric object routes, но ничего не говорит о Борисоглебске и не подтверждает ID `72480`.

## Теллерманов сад / Просторная 4А

В канонической source queue ранее зафиксирован expected object ID:

```text
72480
```

Для него известен точный candidate URL каталога новостроек. На текущем проходе crawler/search не дал читаемое содержимое именно карточки `72480`.

Дополнительные secondary clues:

- ЦИАН маркирует ЖК «Теллерманов сад» как «Проверено наш.дом.рф»;
- Яндекс Недвижимость указывает, что проектные декларации проекта размещены на наш.дом.рф.

Эти признаки поддерживают ожидание, что проект присутствует в контуре ЕИСЖС, но не доказывают, что конкретный ID `72480` относится именно к Просторной 4А.

Поэтому состояние остаётся:

```text
status=candidate_exact_id_unread
primary_content_read=false
object_identity_match=false
```

Acceptance требует прочитать точную primary card и сопоставить минимум название/город/адрес/застройщика или иной уникальный идентификатор объекта.

## Аэродромная 18Г и Сенная 76

Public web-index search по точным адресам не дал надёжной exact primary card.

Это фиксируется как:

```text
no_exact_primary_match_in_search
```

а не как «объекта нет в ЕИСЖС».

Причина: поисковая индексация не является официальным городским фильтром, API или экспортом реестра. Отсутствие результата не доказывает отсутствие записи.

Если конкретный объект юридически не относится к ЕИСЖС/ДДУ-контуру, gap может быть закрыт эквивалентным первичным документом о его реальном статусе, но не вторичным объявлением.

## City-wide reconciliation

Запросы вида `site:наш.дом.рф Борисоглебск` дают нерелевантные карточки из других регионов и не позволяют получить воспроизводимый список всех объектов города.

Поэтому отдельный blocking gap сохраняется до получения одного из вариантов:

- официальный city/region filter ЕИСЖС;
- официальный API/export;
- иной воспроизводимый primary project dataset, позволяющий выбрать Борисоглебск и сопоставить все найденные записи с portal registry.

## Completion

`eiszh_scan_complete=true` разрешён только если:

- unresolved EISZhS scan gaps отсутствуют;
- citywide primary reconciliation отдельно подтверждена;
- accepted target observations подтверждены реальным primary content либо эквивалентным primary evidence;
- source collection и dedicated scan синхронизированы.

## Что scan не меняет

Даже accepted ЕИСЖС card сама по себе не:

- снимает legal/media gates;
- подтверждает актуальную цену или наличие;
- разрешает рекламу;
- снимает `noindex`, если другие critical gates остаются blocked;
- подтверждает продавца конкретной квартиры.

`publication_effect=none` сохраняется на уровне scan.
