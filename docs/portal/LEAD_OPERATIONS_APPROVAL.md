# Утверждение SLA и обработки обращений

Дата обновления: 2026-10-03

## Назначение

Этот пакет отделяет готовые технические контракты от решений, которые может принять только владелец процесса.

Портал уже умеет сформировать структурированное обращение, квалификацию и контекст. Но до утверждения ответственных, рабочего календаря, SLA и отдельной операционной активации нельзя считать обработку операционной.

Канонический реестр:

```text
data/operations/lead-operations-approval.json
```

## Текущее состояние

По реестру при сверке 3 октября 2026 года:

```text
status=requires_owner_approval_not_operational
decision_phase=owner_decisions_pending
approved=1
pending=7
rejected=0
superseded=0
operational_activation_enabled=false
```

Уже утверждено только решение:

```text
system_of_record=supabase:newbuild_leads
```

Остальные семь решений остаются owner-dependent.

## Decision phases

`tools/build-lead-operations-approval-report.mjs` отдельно выводит `decision_phase`, чтобы не смешивать утверждение решений с фактической активацией.

### `owner_decisions_pending`

Есть хотя бы одно решение, которое ещё не approved. Это текущее состояние.

### `decisions_approved_activation_pending`

Все 8/8 decisions утверждены, но:

```text
operational_activation_enabled=false
```

Это важный отдельный handoff: решения уже завершены, но runtime/операционный режим ещё не активирован. В этой фазе Owner release blockers должен показывать отдельный `operational_activation_approval`.

### `activated_ready_for_controlled_test`

Все 8/8 decisions approved и отдельная операционная активация выполнена. Только после этого можно переходить к контролируемому real-lead evidence в рамках остальных launch gates.

Top-level report status пока сохраняет обратную совместимость с действующим package contract:

- до фактической activation — `owner_decisions_required_not_operational`;
- после 8/8 + activation — `operational_activation_ready_for_controlled_test`.

Точная стадия определяется по `decision_phase`.

## Решения владельца

| Решение | Что нужно утвердить | Текущий статус |
|---|---|---|
| Основной владелец | Операционная роль или защищённый идентификатор | Требует решения |
| Резервный владелец | Роль эскалации при недоступности основного | Требует решения |
| Рабочий график | Дни, часы, выходные и часовой пояс | Требует решения |
| SLA первого действия | Срок в рабочее и нерабочее время | Требует решения |
| Распределение | Правила по объекту, типу, квалификации и нагрузке | Требует решения |
| Попытки связи | Количество, каналы и интервалы | Требует решения |
| Причины закрытия | Контролируемый словарь и обязательность комментария | Требует решения |
| Система учёта | `supabase:newbuild_leads` | Утверждено |

## Как утверждать безопасно

Для ответственных в репозиторий нельзя записывать ФИО, телефон или email.

Допустимые варианты:

```text
role:lead_operator_primary
role:lead_operator_backup
secure_reference:crm://team/newbuild-leads
```

Фактическое соответствие роли конкретному сотруднику хранится только в защищённой системе, доступной менеджеру.

## Стартовые гипотезы

Гипотезы помогают принять решение, но не являются утверждённым SLA.

### Первое действие

Roadmap содержит стартовую гипотезу:

```text
не позднее 10 минут в утверждённые рабочие часы
```

После первых 30 реальных обращений значение нужно пересмотреть по фактической нагрузке и contact rate.

### Единая очередь

Безопасная стартовая модель:

```text
новое обращение
→ единая очередь
→ основной владелец
→ распределение по объекту / задаче / нагрузке
→ резерв при просрочке
```

### Попытки связи

Нужно утвердить:

- максимальное число попыток;
- допустимые каналы;
- интервалы;
- правило для нерабочего времени;
- обязательное следующее действие после каждой попытки.

### Причины закрытия

Кандидаты для утверждения:

```text
duplicate
invalid_or_spam
do_not_contact
no_answer_after_policy
not_interested
postponed
no_suitable_option
financing_not_available
other_with_comment
```

## Обязательные поля операционного контура

После активации у каждого тестового обращения должны быть:

```text
lead_id
received_at
lead_owner_ref
backup_owner_ref
assigned_at
first_action_due_at
first_action_at
contact_outcome
next_action
next_action_at
close_reason
source_system
record_locator
```

Портал не заменяет CRM. Эти поля должны храниться в выбранной защищённой системе.

## Условия активации

Операционный режим нельзя включать, пока одновременно не выполнены условия:

1. Утверждены все восемь решений.
2. Роли ответственных разрешаются в защищённой системе.
3. Утверждены рабочий график и часовой пояс.
4. Доступна единая система учёта.
5. Тестовое обращение имеет владельца, первое действие, результат и следующий шаг.
6. Выполнен security review CRM или endpoint.
7. Операционная активация включена отдельным явным изменением.

## Что не изменяется этим пакетом

- реальная заявка не отправляется;
- operational activation не включается автоматически;
- ответственный автоматически не назначается;
- CRM mutation выключен;
- персональные данные в отчёты и GitHub не попадают;
- SLA не объявляется утверждённым;
- реклама и снятие `noindex` не выполняются.

```text

```

CI дополнительно моделирует future state `8/8 approved + activation=false` и требует:

```text

activation_required=true
```

Это гарантирует, что завершённые owner decisions не будут ошибочно смешаны с уже активированным операционным режимом.

## Пакет ограниченного запуска 03.10.2026

Все значения ниже — предложения для одного согласования, а не принятые решения. Machine-readable реестры не изменены. Уже утверждённый `supabase:newbuild_leads` повторно согласовывать не требуется.

### Предлагаемые семь операционных решений

| Decision ID | Предложение | Что требуется от владельца |
|---|---|---|
| primary_owner_assignment | `role:lead_operator_primary`: единый приём входящих | Назначить сотрудника в защищённой системе и подтвердить доступ к очереди |
| backup_owner_assignment | `role:lead_operator_backup`: резерв при отсутствии основного или просрочке | Назначить второго сотрудника в защищённой системе |
| working_schedule | Пн–Пт 09:00–18:00, Сб 10:00–16:00, Вс выходной; Europe/Moscow | Подтвердить, что это график именно портала; график офиса сам по себе не является утверждением |
| first_response_sla | Первое действие до 10 минут в рабочее время; вне графика до 10 минут после следующего открытия | Принять или изменить; SLA означает действие, а не гарантированную связь с клиентом |
| routing_policy | Все новые заявки основному; далее по объекту/задаче/нагрузке; при отсутствии или просрочке — резерву | Подтвердить правила и защищённое соответствие ролей |
| contact_attempt_policy | До 3 попыток: первая по SLA, вторая не ранее чем через 2 рабочих часа, третья на следующий рабочий день; звонок по указанному клиентом номеру; остановка при отказе | Утвердить; не подключать мессенджер автоматически и не повторять контакт после do_not_contact |
| closure_reason_policy | duplicate, invalid_or_spam, do_not_contact, no_answer_after_policy, not_interested, postponed, no_suitable_option, financing_not_available, other_with_comment | Утвердить словарь; для other обязателен комментарий, для postponed — согласованная дата возврата |

После каждого контакта фиксировать outcome и next_action; телефонный клик не считать contacted. Qualified — подтверждённый интерес к покупке и достаточные параметры для согласованного следующего шага; consultation — фактически проведённая консультация. Persistence design коммерческих outcomes пока не deployed: не выдавать эту таблицу за работающий outcome writer.

### QA, аналитика и одна контрольная заявка

- Предлагаемая mobile policy: `emulation_sufficient_for_controlled_launch`. Подтверждённую эмуляцию не переименовывать в physical QA. После утверждения нужен отдельный review применения manual release semantics.
- Предлагаемый analytics provider: `yandex_metrika`. Владелец указывает существующий публичный counter ID и доступ для проверки. Если счётчика нет, это отдельная настройка; не выдумывать ID и не включать внешнюю доставку до разрешения.
- Real lead: ровно одна отправка `homepage_quick_selection` с объекта `all-newbuilds` после явного согласия. Контакт передаётся безопасно, в репозиторий — только secure reference. Проверить запись, атрибуцию, отсутствие дубля, доступ ответственного, первый контакт, outcome и следующий шаг. Успешную запись не выдавать за завершённую консультацию.
- Активацию операций согласовать отдельно после 8/8 решений и проверки ролей, доступа и security; это не разрешение произвольных production mutations.

Основания: `data/qa/mobile-release-policy.json`, `data/analytics/live-provider.json`, `data/release/real-lead-test.json`, `data/operations/lead-operations-approval.json`.

### Юридические факты и проверка

Нужно заполнить фактического оператора, разрешённые к публикации реквизиты, контролируемый канал запросов по данным и состав используемых сервисов. Не подставлять автоматически данные «Этажей» или другого проекта.

Предложение к рассмотрению: закрытые неуспешные заявки хранить 90 дней, затем удалять/обезличивать; сроки согласий, журналов, резервных копий и материалов сделок согласовать отдельно по фактической цели и требованиям. Это гипотеза, не юридический вывод и не готовая retention policy. До утверждения и проверки удаления/backups она не применяется.

Процедура для рассмотрения: запрос поступает в контролируемый канал, подтверждается принадлежность обращения, прекращаются дальнейшие контакты, проверяются применимые основания хранения, выполняется и журналируется разрешённое удаление. Сроки и исключения определяет юридическая проверка; не ставить final_legal_review=passed по общему ответу «согласен».

Нужны отдельные evidence: identity/requisites, privacy channel, retention, withdrawal, processor channels, независимый рекламный статус и кем/когда проверена итоговая редакция. Источник: `data/legal/legal-owner-approval.json`.

### Первая волна общего подбора

Предложение: 7 дней, бюджет 0 ₽, только принадлежащие владельцу бесплатные площадки; начальные размещения — `vk_city_community_catalog_01`, `vk_realtor_page_catalog_01`, `office_qr_catalog_01`. `telegram_city_channel_catalog_01` и `vk_city_community_mortgage_01` сохранить подготовленными до подтверждения конкретных targets. Использовать два уже подготовленных оффера из FIRST_WAVE_RELEASE_PACK.

Владелец указывает точные URL площадок, ответственного и разрешённое окно публикации. Публикация — только после campaign_launch gates; факт внешней публикации записывается отдельно. 7 дней не гарантируют достаточную выборку; если обращений мало, не объявлять CRO-эффект.

Общий подбор не требует BM object-specific approval или полного городского inventory. Но legal, operations, QA, real delivery, live analytics, prepared links и campaign approval остаются обязательными. Перед продвижением закрыть production publication boundary #272, не открывая raw registries/uncleared media.

### Формат одного ответа владельца

1. Принимаю операционные предложения либо перечисляю изменения; основной и резервный сотрудник назначены через защищённую систему.
2. Выбираю mobile policy.
3. Подтверждаю analytics provider и указываю counter ID.
4. Передаю факты оператора/канала данных и результат юридической проверки; retention/withdrawal отмечаю отдельно как принятые или требующие проверки.
5. Отдельно разрешаю одну real lead и передаю безопасный тестовый контакт.
6. После проверок отдельно разрешаю operational activation.
7. Для первой волны подтверждаю точные targets, окно, ответственного и бюджет; разрешение публикации применяется только после всех gates.

Незаполненные пункты остаются pending; принятие предложений не создаёт фактическое evidence доставки, юридической проверки или публикации.
