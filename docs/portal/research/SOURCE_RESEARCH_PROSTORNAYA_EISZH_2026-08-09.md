# Source research — Просторная 4А / ЕИСЖС

Дата проверки: 2026-08-09

Статус: исследовательский evidence. Документ не является подтверждением `accepted`, не снимает `noindex` и не разрешает публикацию изменяемых коммерческих сведений.

## Исходное состояние

В `data/research/source-collection.json` для `prostornaya_4a_eiszh_project_card` уже зафиксирован ожидаемый идентификатор объекта ЕИСЖС `72480`, но точная публичная карточка оставалась `missing`.

Два отдельных первичных документа Просторной 4А уже приняты независимо от этой задачи:

- проектная декларация №36-001139;
- разрешение на строительство №36-04-13-2026.

Они не используются как основание автоматически принимать карточку ЕИСЖС.

## Проверка маршрута ЕИСЖС

Публичные страницы застройщиков и другие индексируемые источники показывают канонический формат точной карточки объекта ЕИСЖС:

`https://наш.дом.рф/сервисы/каталог-новостроек/объект/{object_id}`

Примеры с другими объектами:

- https://наш.дом.рф/сервисы/каталог-новостроек/объект/53883
- https://наш.дом.рф/сервисы/каталог-новостроек/объект/60783
- https://наш.дом.рф/сервисы/каталог-новостроек/объект/57915

На этой основе для уже известного ожидаемого ID `72480` точный candidate URL имеет вид:

`https://наш.дом.рф/сервисы/каталог-новостроек/объект/72480`

## Почему это только candidate_found

Текущий автоматический web-crawler получает HTTP 403 при попытке открыть `наш.дом.рф`, а поисковая выдача не вернула содержимое именно карточки `72480`.

Дополнительно страница ЖК «Теллерманов сад» в ЦИАН показывает маркировку «Проверено наш.дом.рф», то есть внешний marketplace связывает проект с данными ЕИСЖС, но не раскрывает ID карточки в доступном HTML. Это вторичное подтверждение наличия данных в ЕИСЖС, а не первичное доказательство соответствия ID 72480.

Поэтому невозможно честно выполнить acceptance criteria:

- прочитать точную карточку;
- проверить, что на ней действительно отображается ID `72480`;
- подтвердить связь карточки с Просторной 4А по содержимому самой ЕИСЖС.

## Решение

Задачу `prostornaya_4a_eiszh_project_card` допустимо перевести только:

`missing → candidate_found`

с точным candidate URL и датой текущей проверки.

Запрещено в рамках этого прохода:

- переводить задачу в `accepted`;
- использовать candidate URL как самостоятельное подтверждение характеристик объекта;
- повышать `is_public_ready`;
- снимать `noindex`;
- публиковать текущие цены, наличие или иные volatile claims;
- считать права на рендеры/изображения подтверждёнными.

## Следующее условие принятия

`accepted` возможен только после успешного чтения точной карточки либо появления первичного/официального внешнего указателя, который однозначно связывает Просторную 4А с ID `72480`, с сохранением evidence даты и совпавших идентификаторов.
